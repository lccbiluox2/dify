# Dify checkbox 使用方式与注意事项 —— 从源码到完整实战案例

> **核心结论**：Dify 插件工具参数 `type: checkbox` 用于**带 options 的多选**（CheckboxList），UI 侧保存为 `string[]`；但运行期经 `cast_parameter_value` 后，插件 `_invoke` 里**多数情况下收到的是字符串**（常见形态为 Python list 的字符串表示，如 `"['High', 'Medium']"`）。因此：**前端按多选设计，后端必须做归一化解析**，不能假设直接拿到 `list[str]`。
>
> **环境与版本锚点**：Dify 1.12.x / 1.13.x，dify_plugin SDK 0.9.x，源码基于工作区 `dify/web` 与 `dify/api`；实战代码位于 `test-dify/plugin-iot-device-plugin` 与 `test-dify/plugin-dify-iot-device`。
>
> **验证状态**：2026-06-15 已在本地完整跑通，Spring Boot 日志确认 checkbox 多选值正确到达后端。

## 1. checkbox 是什么：与 boolean / select 的区别

Dify 里存在三个极易混淆的类型，开发前必须先分清：

| 类型 | YAML `type` | UI 形态 | 运行期语义 | 典型场景 |
|------|-------------|---------|------------|----------|
| **多选框** | `checkbox` + `options` | CheckboxList，可勾选多个 | 多个 option 的 `value` | 事件等级多选过滤、标签多选 |
| **单选开关** | `boolean` | 单个 Toggle | `true` / `false` | 是否启用某功能 |
| **单选下拉** | `select` + `options` | 下拉框，只能选一个 | 单个 `value` 字符串 | 状态单选（在线/离线） |

### 1.1 前端 FormTypeEnum 定义

```typescript
// web/app/components/header/account-setting/model-provider-page/declarations.ts
export enum FormTypeEnum {
  select   = 'select',
  checkbox = 'checkbox',   // 多选 + options
  boolean  = 'boolean',    // 单开关
  // ...
}
```

### 1.2 工作流「开始节点」里的 checkbox 不要混淆

若把工作流应用「发布为工具」，开始节点变量类型 `checkbox` 会被映射为 **`boolean`**（单开关），**不是**插件工具的多选 checkbox：

| 开始变量类型 | 发布为工具后的 ToolParameter 类型 |
|-------------|----------------------------------|
| `select` | `select` |
| `checkbox` | **`boolean`**（单开关） |
| `text-input` | `string` |

**结论**：要做「高/中/低多选」，应使用**插件工具 YAML 的 `type: checkbox` + `options`**，而不是工作流开始节点的 checkbox 变量。

### 1.3 与 `type: array` 的取舍

| 方案 | UI | 插件 `_invoke` 收到的值 | 推荐度 |
|------|-----|------------------------|--------|
| `checkbox` + `options` | 多选框，用户体验好 | 字符串（需解析） | ★★★ 推荐 |
| `array` | JSON 编辑器 | 原生 `list` | 仅调试 / 高级用户 |

团队后续凡是要给用户多选固定选项，**优先 checkbox**；在 `_invoke` 入口统一调用 `parse_checkbox_param` 即可。

## 2. 源码解析：UI、传参、类型转换全链路

### 2.1 前端：CheckboxList 保存 string[]

工具节点参数渲染在 `form-input-item.tsx`。当 `_type === checkbox` 且为常量模式时，渲染 `CheckboxList`：

```typescript
// web/app/components/workflow/nodes/_base/components/form-input-item.tsx
const handleCheckboxListChange = (selected: string[]) => {
  onChange({
    ...value,
    [variable]: {
      ...varInput,
      type: VarKindType.constant,
      value: selected,   // ← UI 保存 string[]
    },
  })
}
```

解析已有值时支持 `string[]`、单个 `string`、或 default 为数组：

```typescript
// web/app/components/workflow/nodes/_base/components/form-input-item.helpers.ts
export const getCheckboxListValue = (currentValue, defaultValue, availableOptions) => {
  let current: string[] = []
  if (Array.isArray(currentValue))
    current = currentValue as string[]
  else if (typeof currentValue === 'string')
    current = [currentValue]
  else if (Array.isArray(defaultValue))
    current = defaultValue as string[]
  // ...
}
```

**要点**：checkbox 在前端画布上始终是**字符串数组语义**。

### 2.2 form 字段：参数出现在哪个区域

| `form` 值 | UI 区域 | 存储字段 | 适用 |
|-----------|---------|----------|------|
| `form` | 工具节点「设置」区 | `tool_configurations` | 固定多选，便于手工测试 checkbox |
| `llm` | 「输入变量」区 / LLM 填参 | `tool_parameters` | Agent 自动填参 |

**Checkbox 演示建议先用 `form: form`**，在设置区勾选，便于验证 UI 与传参；稳定后再按需改为 `llm`。

### 2.3 后端：cast_parameter_value 会把 checkbox 转成 string

这是最容易踩坑的地方：

```python
# api/core/plugin/entities/parameters.py
def cast_parameter_value(typ: StrEnum, value: Any, /):
    match typ.value:
        case (
            PluginParameterType.STRING
            | PluginParameterType.SELECT
            | PluginParameterType.CHECKBOX      # ← checkbox 与 select 同分支
            | PluginParameterType.DYNAMIC_SELECT
        ):
            if value is None:
                return ""
            else:
                return value if isinstance(value, str) else str(value)
                # list → str(list)，例如 "['High', 'Medium']"
```

工具调用前会执行类型转换：

```python
# api/core/tools/__base/tool.py
def _transform_tool_parameters_type(self, tool_parameters):
    for parameter in self.entity.parameters or []:
        if parameter.name in tool_parameters:
            result[parameter.name] = parameter.type.cast_value(tool_parameters[parameter.name])
```

### 2.4 运行期传参链路（插件工具）

```
工作流工具节点 UI 勾选 threat_severity
    ↓  value: ["High", "Medium"]
ToolManager 解析 tool_configurations（form: form）
    ↓
Tool.invoke → _transform_tool_parameters_type
    ↓  cast_parameter_value(CHECKBOX, ...)
PluginTool._invoke → convert_parameters_to_plugin_format
    ↓
插件 Python _invoke(tool_parameters)
    ↓  threat_severity ≈ "['High', 'Medium']"  （字符串！）
HTTP 请求后端 API
```

## 3. YAML 定义规范与常见写法错误

### 3.1 正确写法（标准模板）

```yaml
parameters:
  - name: threat_severity
    type: checkbox
    required: false
    label:
      en_US: Threat Severity
      zh_Hans: 事件等级
    human_description:
      en_US: Multi-select threat severity level filter
      zh_Hans: 事件等级多选过滤
    llm_description: "Multi-select threat severity: High, Medium, Low. Leave empty to return all events."
    form: form
    options:
      - value: "High"
        label:
          en_US: High
          zh_Hans: 高
      - value: "Medium"
        label:
          en_US: Medium
          zh_Hans: 中
      - value: "Low"
        label:
          en_US: Low
          zh_Hans: 低
```

### 3.2 常见错误对照

| 错误写法 | 问题 | 正确做法 |
|----------|------|----------|
| `options` 下缺少 `-` 列表项 | YAML 结构非法 | 每个 option 以 `- value:` 开头 |
| `en_us` / 全角冒号 `zh_Hans：` | i18n key 不匹配 | 统一 `en_US`、`zh_Hans` |
| `value: High` 不加引号 | 特殊字符或大小写问题 | 建议 `"High"` |
| 只有 `type: checkbox` 没有 `options` | UI 无选项可勾选 | 必须提供 `options` |
| 把 `checkbox` 当 `boolean` 用 | 语义完全不对 | 开关用 `boolean`，多选用 `checkbox` |
| `_invoke` 里 `if isinstance(v, list)` 就结束 | 运行期多数是 str | 必须 `parse_checkbox_param` |

### 3.3 value 与 label 的分工

- **`options[].value`**：传给后端 / 写入 `_invoke` 的**业务值**（建议与 API 枚举一致，如 `High`）
- **`options[].label`**：UI 展示文案（如 `高`），不影响传参

**团队约定**：value 用英文枚举或稳定 ID，label 做多语言展示。

## 4. 插件侧最佳实践：parse_checkbox_param

### 4.1 设计原则

1. **入口统一解析**：每个 checkbox 参数进 `_invoke` 后第一步调用解析函数  
2. **兼容多种输入形态**：`list`、`"['A','B']"`、`"A,B"`、单值 `"A"`、空值  
3. **白名单校验**：只接受 options 里定义的 value，非法值抛清晰错误  
4. **日志打印 raw + parsed**：便于对照 Dify 实际传值  

### 4.2 推荐实现（本项目已验证）

文件：`test-dify/plugin-iot-device-plugin/tools/filter_threat_severity.py`

```python
import ast
import json
from typing import Any

ALLOWED_SEVERITIES = frozenset({"High", "Medium", "Low"})


def parse_checkbox_param(raw: Any) -> list[str]:
    """将 Dify checkbox 运行期参数归一化为 list[str]。"""
    if raw is None or raw == "":
        return []

    if isinstance(raw, list):
        return _normalize_values(raw)

    if isinstance(raw, str):
        text = raw.strip()
        if not text or text == "[]":
            return []

        if text.startswith("["):
            try:
                parsed = ast.literal_eval(text)
                if isinstance(parsed, list):
                    return _normalize_values(parsed)
            except (ValueError, SyntaxError):
                pass
            try:
                parsed = json.loads(text)
                if isinstance(parsed, list):
                    return _normalize_values(parsed)
            except json.JSONDecodeError:
                pass

        if "," in text:
            return _normalize_values(part.strip() for part in text.split(","))

        return _normalize_values([text])

    return _normalize_values([raw])


def _normalize_values(values: Any) -> list[str]:
    normalized: list[str] = []
    for value in values:
        candidate = str(value).strip()
        if not candidate:
            continue
        for allowed in ALLOWED_SEVERITIES:
            if allowed.lower() == candidate.lower():
                if allowed not in normalized:
                    normalized.append(allowed)
                break
        else:
            raise ValueError(
                f"Unsupported threat severity: {candidate}. "
                f"Allowed values: {', '.join(sorted(ALLOWED_SEVERITIES))}"
            )
    return normalized
```

### 4.3 _invoke 中的标准用法

```python
raw_value = tool_parameters.get("threat_severity")
try:
    severities = parse_checkbox_param(raw_value)
except ValueError as exc:
    yield self.create_text_message(self.log.error_text("threat_severity 参数无效", ctx, str(exc)))
    return

self.log.info(f"checkbox 原始值={raw_value!r} 解析后={severities!r}")

# 传给 HTTP API
params = {"threat_severity": severities} if severities else None
response, err = self.run_http(ctx, "GET", url, params=params)
```

### 4.4 各输入形态解析结果

| `_invoke` 收到的 raw | 解析结果 |
|---------------------|----------|
| `None` / `""` | `[]` |
| `"['High', 'Medium']"` | `["High", "Medium"]` |
| `["High", "Medium"]`（少数路径） | `["High", "Medium"]` |
| `"High,Medium"`（LLM 可能这样传） | `["High", "Medium"]` |
| `"High"` | `["High"]` |

## 5. 后端 API 最佳实践：如何接收多选参数

### 5.1 推荐方式：重复 query 参数

```http
GET /api/dify-checkbox-demo/events/filter?threat_severity=High&threat_severity=Medium
```

Spring Boot：

```java

public ResponseEntity<?> filterEvents(
    @RequestParam(name = "threat_severity", required = false) List<String> threatSeverity
) {
    log.info("收到 checkbox 演示过滤请求 threat_severity={}", threatSeverity);
    // ...
}
```

Python `requests` 传参：

```python
params = {"threat_severity": ["High", "Medium"]}
requests.get(url, params=params)
# → threat_severity=High&threat_severity=Medium
```

### 5.2 备选方式：逗号分隔（与 focus_ip 类字段一致）

```http
GET /api/xxx?threat_severity=High,Medium
```

后端 `split(",")` 解析。插件侧需在 HTTP 层 `",".join(severities)`。

**团队建议**：新接口优先 **List + 重复 query**；若已有 comma-separated 约定，则在 `parse_checkbox_param` 之后统一 join。

### 5.3 空选的语义

本案例约定：

- **不传 / 空列表** → 返回全部 mock 事件（5 条）  
- **传 High + Medium** → 只返回等级为 High 或 Medium 的事件（3 条）  

业务接口应明确文档化「空选 = 不过滤 / 全量」语义，避免前后端理解不一致。

## 9. 注意事项与踩坑清单

### 9.1 类型与语义

| 坑 | 说明 | 规避 |
|----|------|------|
| checkbox 当 boolean | 期望多选却只出现一个开关 | 确认 YAML 是 `checkbox` + `options` |
| 开始节点 checkbox 发布为工具 | 变成 boolean 单开关 | 多选必须用插件工具参数 |
| 直接用 `type: array` 期望 checkbox UI | 只会出现 JSON 编辑器 | 要 UI 就用 checkbox |

### 9.2 运行期传值

| 坑 | 说明 | 规避 |
|----|------|------|
| `_invoke` 里 `isinstance(v, list)` | cast 后多为 str | 使用 `parse_checkbox_param` |
| 不打印 raw 值 | 无法排查 Dify 实际传参 | 日志记录 `raw` 与 `parsed` |
| value 大小写不一致 | `high` vs `High` 过滤失败 | 解析时做 case-insensitive 归一化 |

### 9.3 YAML 与 i18n

| 坑 | 说明 | 规避 |
|----|------|------|
| options 结构错误 | 插件加载失败 | 每项 `- value:` 独立列表元素 |
| `en_us` 小写 | label 不显示 | 统一 `en_US` |
| value 用中文 | 与后端枚举不一致 | value 用稳定英文，label 用中文 |

### 9.4 网络与部署

| 坑 | 说明 | 规避 |
|----|------|------|
| 插件 URL 填 localhost | 容器内连不上宿主机 Spring | 用局域网 IP |
| 未重新打包安装插件 | 画布看不到新工具 | 改 YAML 后重新 `package.cmd` |

### 9.5 form 分区

| 坑 | 说明 | 规避 |
|----|------|------|
| `form: form` 却在输入变量区找 | checkbox 在设置区 | 展开节点下方设置 |
| 想 LLM 自动填多选 | 需改 `form: llm` 并写好 llm_description | LLM 可能传 `"High,Medium"` 字符串，解析函数需兼容 |

## 总结

| 维度 | 要点 |
|------|------|
| **是什么** | `checkbox` = 带 options 的多选 CheckboxList |
| **不是什么** | 不是 `boolean` 开关，不是工作流开始节点的 checkbox（发布为工具后会变 boolean） |
| **UI 存什么** | `string[]`，如 `["High","Medium"]` |
| **_invoke 收到什么** | 多数是 **字符串**，如 `"['High', 'Medium']"` |
| **必须做什么** | 插件入口 `parse_checkbox_param`，后端 `List<String>` 接收 |
| **怎么测** | 先 curl API，再工作流设置区勾选，对照两端日志 |
| **参考实现** | `filter_threat_severity` 全套（已 2026-06-15 验证通过） |

> **团队规范**：后续所有 checkbox 相关开发，以本文案例为模板——YAML 结构、`parse_checkbox_param` 解析、Spring `List<String>` 接参、日志与验收清单五项齐全，再合并到业务接口。
